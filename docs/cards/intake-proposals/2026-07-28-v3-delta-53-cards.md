## B3 — CARD-029 is deleted; the measurement becomes a PR test plan

`depends_on` means "after", so a measurement card downstream of the port it gates can never gate
it. The measurement is manual and unautomatable, which is exactly what a PR test plan is for.

**CARD-029 (v2) is removed.** Its three criteria move onto the porting card as a
`## Test plan (manual, PR body)` section — reviewed by a human at PR time, before merge, which is
where a gate on an unautomatable check actually binds:

```markdown
## Test plan (manual — must be completed before merge)
- [ ] Live run against the real OpenRouter API records `cached_tokens` on lens calls 2 and 3
- [ ] Both readings are non-zero and pasted into this PR
- [ ] If either reads zero, re-run before concluding — OpenRouter routes the same model to
      different providers call to call, so one zero proves nothing
- [ ] Reading is consistent with Gate 1's 91% cache-read figure
```

The same treatment applies to **CARD-030** (githubkit confirmation), the other live verification —
REQ-028 now names both as exemptions. Its A4 defect is fixed too: the "close CARD-031/032 as
superseded" instruction moves from an acceptance criterion into the card's Notes, since a card
cannot close other cards.

## B4 — `prior_rounds` splits three ways, marker-first

The 15 lines at `review.py:672-686` become three clauses, and **`core/marker.py` owns the
substance** — recovering the round number and last-reviewed SHA is marker parsing, and the marker
is this program's only state.

| Piece | Home | Card | AC |
|---|---|---|---|
| Parse a review body into `(round, sha)` | `core/marker.py` | CARD-007 | `MARKER_RE` parsing is pure, takes a body string, returns the pair or `None` |
| Fetch prior review bodies for a PR | `adapters/github.py` | CARD-023 | Returns bodies only; performs no parsing |
| Orchestrate the two, apply `max_rounds` | `app/select.py` | CARD-033 | Calls the adapter, folds through the core parser, applies the round cap |

## A2 — `seg` and `_blocks` go to `core/prompt.py`

They are pure and they are prompt structure. If they followed the OpenRouter section into
`adapters/`, then `core/prompt.py`'s `build_shared_blocks` could not call them without breaking
REQ-009 — the boundary test would fail on the first prompt card.

- **CARD-012** (`core/prompt`) takes `seg` (`review.py:386-398`) and `_blocks` (`:399-402`).
- **CARD-026** (`openrouter` relocation) leaves them behind. `strip_fence` correctly stays with
  the adapter — it parses a model *response*, not a prompt.
