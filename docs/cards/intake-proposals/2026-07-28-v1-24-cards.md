# Proposed backlog — modular refactor of pr-review-bot

Spec: `docs/superpowers/specs/2026-07-28-modular-refactor-design.md` (27 requirements, REQ-001..REQ-027).
Existing board: **empty** — no cards, no milestones. These are the first cards.
Layers (config order): `infra`, `core`, `adapters`, `app`. `gate_layer: core`.
`size_limit: 500` changed lines including tests. `size_exclude`: lock files, `vendor/**`,
`node_modules/**`, `docs/cards/**`.

Baseline facts the estimates rest on: `review.py` is 2,577 lines; the context pack is ~1,380 of
them; `pack_changed_files` alone is 210 lines; the test suite is 263 tests across 4 files
totalling 3,434 lines, of which `tests/test_context.py` is 2,304.

## CARD-001 — Continuous integration runs the test suite on every pull request
- type: task | layer: infra | reqs: [REQ-018] | depends_on: []
- **Why:** Nothing later in this backlog can be validated until a pipeline exists to validate it.
  The repository currently has no `.github/` directory at all.
- Acceptance criteria:
  - [ ] `.github/workflows/ci.yml` runs `python3 -m unittest discover -s tests -t .` on every pull request and reports status (REQ-018)
  - [ ] A pull request with a deliberately failing test shows a red check (REQ-018)
  - [ ] The workflow completes without installing anything beyond the repository's own requirements (REQ-018)

## CARD-002 — Build a container image on every pull request
- type: task | layer: infra | reqs: [REQ-017, REQ-018, REQ-019, REQ-020, REQ-021] | depends_on: [CARD-001]
- **Why:** The deployment currently ships a hand-copied duplicate of `review.py` that is 999 lines
  and byte-identical to the pre-context-pack `main`. An image built from this repository closes that
  gap immediately, and building it on every PR stops it rotting as the refactor proceeds.
- Acceptance criteria:
  - [ ] `Dockerfile` produces an image whose entrypoint is `python3 /app/review.py` (REQ-019)
  - [ ] `doctrine/` is present inside the image (REQ-020)
  - [ ] Bytecode is precompiled at build time and the container runs a review with a read-only root filesystem (REQ-021)
  - [ ] `requirements.txt` and `requirements-dev.txt` exist, and no dev dependency appears in the image (REQ-017)
  - [ ] CI builds the image and smoke-runs `--help` on every pull request (REQ-018)

## CARD-003 — Publish the image to GHCR on a tagged release
- type: task | layer: infra | reqs: [REQ-018] | depends_on: [CARD-002]
- **Why:** Makes the image consumable by the Kubernetes deployment, following the pattern the

- Acceptance criteria:
  - [ ] `.github/workflows/release.yml` pushes `ghcr.io/stebennett/pr-review-bot:X.Y.Z` on a version tag (REQ-018)

## CARD-004 — Synthetic fixtures and the golden prompt-byte harness
- type: task | layer: infra | reqs: [REQ-022, REQ-023, REQ-024, REQ-026] | depends_on: [CARD-001]
- **Why:** The 263 tests will themselves change during the dependency swaps, so the safety net has
  to be anchored to something that survives them. Assembled prompt bytes are deterministic where
  findings are stochastic, and capturing them costs no model calls.
- Acceptance criteria:
  - [ ] A committed fixture set of five diffs plus a small source tree covers: budget-filling, hunk windowing, the dropped-file trailer, adversarial backtick fences, and an all-new-files PR (REQ-023)
  - [ ] Goldens record, byte for byte, each lens's system and user blocks for all three lenses, the verdict prompt, and `ctx.pack` / `ctx.notes` / `ctx.requirements` (REQ-022)
  - [ ] A test regenerates the goldens and fails on any byte difference (REQ-024)
  - [ ] The harness makes zero network calls and no fixture depends on a checkout outside the repository (REQ-023, REQ-026)

## Proposed milestones

### M1 — Pipeline and safety net
**Goal:** Close the deployment gap and make every later pull request independently validated.
**Exit criteria:** A tagged build publishes a working image to GHCR; CI runs tests, an image build and the golden comparison on every PR.
**Cards:** CARD-001, CARD-002, CARD-003, CARD-004

### M2 — Pure core extracted
**Goal:** The pure, I/O-free logic lives in `reviewer/core/` behind an enforced import boundary.
**Exit criteria:** The import-boundary test passes; both prompt invariants are structural; goldens byte-identical.
**Cards:** CARD-005, CARD-006, CARD-007, CARD-008, CARD-009

### M3 — The pack behind a port
**Goal:** The degradation ladder becomes a choice of `SourceTree` implementation.
**Exit criteria:** No assembler contains `root is None` branching; all four rungs are implementations.
**Cards:** CARD-010, CARD-011, CARD-012, CARD-013, CARD-014, CARD-015

### M4 — Adapters isolated
**Goal:** Every side effect lives at the edge.
**Exit criteria:** No `core/` module logs or performs I/O; `openrouter` relocated byte-identical.
**Cards:** CARD-016, CARD-017

### M5 — Dependencies adopted
**Goal:** The hand-rolled HTTP, auth and client code is replaced where a library is better.
**Exit criteria:** No `openssl` subprocess; explicit timeouts; goldens byte-identical.
**Cards:** CARD-018, CARD-019, CARD-020

### M6 — App wired, monolith retired
**Goal:** `review.py` becomes an entry point rather than the program.
**Exit criteria:** `review.py` is three lines; every documented command works; goldens byte-identical.
**Cards:** CARD-021, CARD-022

### M7 — Tests restructured
**Goal:** The suite mirrors the package and uses fakes rather than scaffolding.
**Exit criteria:** pytest green in CI; no test lost; layout mirrors source.
**Cards:** CARD-023

### M8 — Worktree head verification
**Goal:** Land the one intended behaviour change in isolation.
**Exit criteria:** Stale worktree warns, degrades and still packs; goldens move only in the label.
**Cards:** CARD-024
